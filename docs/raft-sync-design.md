# 去中心化数据同步方案（Raft 集群版）

> 状态：设计已确认，待实施
> 版本：v1.1（2026-10-24）
> 适用版本：planning v0.3.x+

## 一、应用场景

- **局域网环境**下的多台电脑（台式机 + 笔记本）之间数据相互同步
- 无中心服务器、无第三方云服务参与，数据不出局域网
- 单用户、多设备；同一时间通常只在一台设备上编辑

## 二、总体架构

```
┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│  台式机 A         │   │  台式机 B         │   │  笔记本 C         │
│  Raft Node #1    │◄─►│  Raft Node #2    │◄─►│  Raft Node #3    │
│  (Leader)        │◄──┴───────┬─────────┘   │  (Follower)       │
│  SQLite          │           │              │  SQLite           │
│  :7878(可改)      │           └──────────────┤  :7878(可改)      │
└──────────────────┘      TCP / 局域网         └──────────────────┘

  所有写入 → 提交给 Leader → 复制到多数派 → 各节点本地 SQLite 顺序应用
  → 任意节点本地读，数据强一致
```

**核心收益**：写入全部经过单一日志定序，**天然零冲突**——不存在"合并"问题，只有"复制"问题。

## 三、技术选型

| 组件 | 选择 | 说明 |
|------|------|------|
| 共识库 | `openraft` 0.9 | 活跃维护、存储/网络层全自定义；TiKV 系 `raft-rs` 过于底层 |
| 节点间通信 | `axum` HTTP（内嵌监听）+ `reqwest`（出站） | 默认端口 `7878`，**每节点可独立修改** |
| 日志与状态机存储 | SQLite 新增表（复用现有库） | `raft_log` / `raft_state`，快照复用 `VACUUM INTO` |
| 节点身份 | `node_id`(uuid) + 监听地址 + 节点名称 | 持久化于 `meta` 表 |
| 安全 | 集群令牌（创建集群时生成，加入时校验） | 局域网内 v1 不上 TLS，令牌防陌生设备 |

## 四、状态机设计

Raft 复制的是**操作日志**，状态机 = 本地 SQLite：

```rust
enum RaftCommand {
    UpsertEvents(Vec<Event>),                // 新增/修改事件
    DeleteEvents(Vec<String>),               // 删除事件
    SetKv { key: String, value: String },    // 四象限/灵感笔记/绩效
    SetClusterConfig(ClusterConfig),         // 集群配置(含时间范围, 见第六节)
}
```

### 写入路径（前端零改动）

```
db_save_events(全量数组)
   │
   ├─ Rust 内部 diff: 新增/变更/删除
   │
   ├─【单机模式】直接写本地 SQLite(现行为不变)
   │
   └─【集群模式】
        ├─ 事件在同步时间范围内 → RaftCommand → Leader 提议 → 复制 → 各节点 apply
        └─ 事件在范围外 → 本地直写(不进集群, 见第六节)
```

- `store/events.js` 等前端 API 完全不变
- diff 与范围过滤均在 Rust 侧完成，一套入口两种路由

### 读路径

各节点读本地 SQLite。跟随者读为最终一致（滞后通常 <100ms）；需要线性一致读的场景后期用 ReadIndex 优化。

## 五、集群组建与成员管理

### 1. 创建集群（首节点）

```
设置页 → [创建集群] → 生成集群令牌(6位码) + 默认同步范围 → 单节点集群(自选主)
```

### 2. 手动填 IP 加入

```
新节点 设置页 → [IP:端口] + [令牌] → [加入集群]
   ├─ 向既有节点: POST /cluster/join { node_id, addr, token }
   ├─ 校验令牌 → Leader 执行 add_learner(新节点)   ← 先当学习者拉数据
   ├─ 追平日志后 → change_membership 提升为投票成员
   └─ 新节点: 已加入 · 数据同步中… → 已同步
```

### 3. 掉线自动重连

| 场景 | 行为 |
|------|------|
| 暂时失联（合盖/拔网线） | Raft 心跳/选举自动处理，恢复后增量追日志，无人工干预 |
| 长期离线后回归 | 成员身份保留 → 自动追平；落后过多走快照（`VACUUM INTO` 全量+增量） |
| Leader 故障 | 多数派自动选主（典型 <2s），写入短暂中断后自动恢复 |

### 4. 退出与移除

- 成员主动退出：`remove_member(自身)` → 集群变更成员表 → 回到单机模式（保留数据副本）
- 移除他机：Leader 侧执行 `change_membership` 收缩；被移除节点收到通知转单机模式

## 六、同步范围

### 数据范围

| 数据 | 是否同步 | 存储位置 |
|------|---------|---------|
| 事件（events 表） | ✅（受时间范围约束） | `~/Documents/planning/planning.db` |
| 四象限 / 灵感笔记 / 绩效（kv） | ✅ | 同上 |
| 应用设置（主题/时间范围/API Key 等） | ❌ 各机本地 | 本地 SQLite `settings` 键 |
| 集群配置（令牌/时间范围/成员表） | ✅ 经 Raft 复制 | `cluster.config` 键 |
| 备份目录 | ❌ 各自本地 | 快照机制覆盖 |

### 时间范围同步 ⭐

**目的**：限制同步的事件时间跨度，减少日志量与快照体积（如只同步"近一年 + 未来"）。

**配置（集群级，经 Raft 复制，各节点一致）**：

```jsonc
// cluster.config（ raft 复制的 kv ）
{
  "token": "482913",
  "syncSince": "2025-10-24",     // 绝对日期: 仅同步 date >= syncSince 的事件
  "members": [...]
}
```

**机制（关键：保证 Raft 确定性）**：
- 过滤发生在 **Leader 提议阶段**：范围内的事件进 Raft 日志；范围外事件**只写本地、不进集群**
- 使用**绝对日期**（`syncSince`）而非"相对当前时间的 N 个月"——相对时间会导致各节点判定不一致，破坏状态机确定性
- 跟随者 apply 时不过滤（日志里都是已过滤的命令，天然一致）

**边界规则**：
| 场景 | 行为 |
|------|------|
| 创建/编辑范围外事件 | 本地生效，不同步（UI 无感，正常使用） |
| 删除范围外事件 | 它从未进集群 → 本地直删即可 |
| 修改 syncSince 向前扩展 | 仅影响**之后**的提议；已存在的旧事件不自动回灌。提供手动操作「重扫本地事件入库」按新范围补传 |
| 修改 syncSince 向后收缩 | 已在集群中的事件不自动清除；提供「按新范围清理本节点」说明（仅建议，不强制） |

**UI**：设置页集群卡片内
```
同步起始日期  [2025-10-24 📅]  （仅同步此日期之后的事件, 集群级配置）
提示: 修改后新事件按新范围同步; 历史事件可用「重扫入库」补传
[重扫本地事件入库]
```

## 七、仲裁与可用性

Raft 写入需要**多数派**在线：

| 节点数 | 容忍故障 | 建议 |
|--------|---------|------|
| 2 | 0 | ⚠️ 不推荐（任一台离线即无法写入） |
| 3 | 1 | **推荐最小配置**（台式机×2 常开 + 笔记本×1） |
| 5 | 2 | 节点更多时使用 |

### 离线模式兜底（已确认）

```
失去仲裁 → 界面提示"集群不可用" → 用户可开启「离线模式」
  ├─ 写入进本地 pending 队列(不进 Raft)
  ├─ 重连后逐条重放提交给 Leader
  ├─ 同 id 冲突: 应用层 LWW 兜底(updatedAt) + 旧值存档 conflicts/
  └─ 显式开关, 不静默分叉
```

## 八、端口与网络

- 每节点独立监听端口，默认 `7878`，**设置页可改**（本机配置，不复制）
- 加入集群时填写 `IP:端口`，端口随成员表记录
- 监听 `0.0.0.0`；对外通告本机局域网 IP（多网卡时设置页可选）
- macOS 首次监听有防火墙授权弹窗，安装/使用文档说明
- 集群令牌校验失败 → 拒绝加入；未携带令牌的 Raft RPC → 拒绝

## 十二、风险与对策

| 风险 | 对策 |
|------|------|
| openraft 存储适配器学习曲线 | 参照官方 memstore 示例逐方法对齐 SQLite |
| 笔记本频繁睡眠失联 | 正常 Raft 行为；UI 明示"离线≠丢数据"，恢复自动追平 |
| 两节点集群无仲裁 | 文档明示推荐 ≥3 节点；2 节点场景引导使用离线模式 |
| 时间范围改动历史不回灌 | 明确边界规则 + 手动「重扫入库」操作 |
| 局域网恶意接入 | 集群令牌校验；后续可选 TLS |
